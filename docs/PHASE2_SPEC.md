# Phase 2 — The Firm Module: Implementation Specification

**Project**: Impôts · **Phase**: 2 of 4 · **Prerequisites**: Phase 0+1 as built; review verdicts of 2026-08-29 (docs/REVIEW_2026-08-29.md)
**Audience**: the implementing agent. Convention unchanged: **[VERIFIED]** = executed live on 2026-08-28/29 against `openfisca-core 44.7.0`; **[ENACTED]** = checked against post-LF-2026 secondary sources on 2026-08-29 and to be confirmed against BOFiP/Légifrance during the build (statute paths given). The engineering pattern in §1 ran green in a prototype; `scripts/verify_firm_engine.py` reproduces it.
**Why this phase matters**: the Phase 0 audit found no open, general-purpose firm-tax simulation for France — none. This is the project's claim to mattering. It is also where overreach is easiest: the discipline that saved Phases 0–1 (mechanical first, fidelity labelled, validation uncalibrated) applies with more force here, because firm microdata is *not* open the way household survey data is, and every firm financial in this module will be synthetic.

## 0. What Phase 2 is

A new package, `src/impots/entreprises/`, that answers: **what does a change to firm taxation cost, and who bears it by sector and size** — for IS (with its surcharges), CVAE, C3S — computed mechanically over a synthetic firm population built from SIRENE × ESANE, with its own reconciliation report in the same format and under the same epistemic rules as Phase 1's.

**Definition of done**:
1. `impots entreprises build` produces `data/processed/firms_{vintage}.parquet` from manifested open inputs, deterministically.
2. `impots entreprises run --reform reform_is.json` prices a firm-tax reform: aggregate Δ revenue by instrument, incidence table by NAF section × size class, distribution of effective rates.
3. `reports/reconciliation_entreprises.md` generated by code; IS-net line within its declared tolerance or the miss investigated in writing.
4. Firm golden tests green with **relative** tolerance (§1.4); household suite untouched and green.
5. API `POST /entreprises/simulate` + a third UI tab with the L1-firm banner.
6. Every §0.5 pre-flight item closed and logged.

**Out of scope — refuse**: intégration fiscale / groups (needs LIFI, CASD-gated), tax credits (CIR/CICE history), exact CFE (communal valeur locative bases; §2.5 says what to do instead), employer-contribution reforms (the household engine already carries cotisations at the employee level; wiring firm wage bills to it is Phase 3's macro loop), behavioural response of any kind (Phase 3), TVA (Phase 4), DOM specifics, micro-entreprise IR regimes.

## 1. The engine pattern **[VERIFIED]**

### 1.1 A second TaxBenefitSystem, one custom entity

Firms are not people: do not graft an entity into openfisca-france. Build a sibling system on openfisca-core (same pinned version — one engine, two rule sets):

```python
from openfisca_core.entities import build_entity
from openfisca_core.taxbenefitsystems import TaxBenefitSystem

Entreprise = build_entity(key="entreprise", plural="entreprises",
                          label="Unité légale soumise à l'IS", is_person=True)

class FirmSystem(TaxBenefitSystem):
    def __init__(self):
        super().__init__([Entreprise])
        self.load_parameters(PARAMS_DIR)      # YAML tree, dated values — same as upstream
        for v in VARIABLES: self.add_variable(v)
```

Verified end-to-end: YAML parameters load; `parameters(period).impot_societes.taux_normal` resolves by date; annual variables with vectorised formulas compute; **N=500 000 firms in 0.01 s** for an IS formula (real formula set will be slower; still trivially interactive — no batch machinery needed on the firm side); NaN=0; the household engine's `Reform`/`modify_parameters` API works identically and leaves the baseline untouched. `SimulationBuilder` needs only `create_entities` + `declare_person_entity` — a single-entity system has no role wiring, so Phase 1's subrole trap does not exist here.

### 1.2 Naming gotcha **[VERIFIED]**

A parameter directory named `is` breaks attribute access on the parameter tree (Python keyword — `parameters.is_` resolves to nothing useful). Name the node **`impot_societes`**. Audit all node names against Python keywords.

### 1.3 Reform whitelist

Extend the Phase 0 pattern, never raw paths. `FirmReformSpec` v1 knobs: `is_taux_normal`, `is_taux_reduit`, `is_plafond_taux_reduit`, `is_pme_plafond_ca`, `cs_taux`, `cs_abattement`, `cebge_seuils_et_taux` (paired list), `cvae_taux_max`, `c3s_taux`, `c3s_abattement`. Same canonical-JSON cache key, and a `verify_*` read-back for anything barème-shaped (D-007's lesson is portable).

### 1.4 Precision **[VERIFIED]**

openfisca-core computes in float32. At firm scale (IS of a large firm ~1e8 €) that is ~7 significant digits: the prototype's hand-check differed by 2 € on a 34.8 M€ liability. Consequences: firm golden tests assert **relative tolerance 1e-5**, never ±2 €; aggregates are reported to the 0.1 bn; and no per-firm figure is ever displayed to more precision than float32 warrants.

`scripts/verify_firm_engine.py` (shipped) encodes 1.1–1.4; keep it green like its two siblings.

## 2. Legislation to encode **[ENACTED — confirm each against BOFiP at build time]**

All parameters as dated YAML from their statutory start dates (encode from 2022 where cheap, 2024 minimum), so backdated runs and the 2030 CVAE path both fall out of the parameter tree.

### 2.1 Impôt sur les sociétés (CGI art. 205 s., 219)
- Taux normal **25 %** (2022→). Taux réduit PME **15 %** on the first **42 500 €** of benefice (CGI 219-I-b), eligibility CA ≤ **10 M€** + capital conditions — model the capital conditions as an input boolean defaulting true for eligible-CA firms. A PLF 2026 amendment proposed raising the 42 500 € to 100 000 €; the enacted LF 2026 figure to confirm at BOFiP — encode whatever BOFiP says, with the date.
- Contribution sociale sur l'IS (CGI 235 ter ZC): **3.3 %** of IS exceeding **763 000 €**, exemption CA < 7.63 M€.
- **CEBGE** (contribution exceptionnelle, LF 2025, renewed LF 2026): 2025 thresholds CA ≥ 1 bn / 3 bn; 2026 raised to **1.5 bn** / 3 bn; rates **20.6 % / 41.2 %** of an IS-based assiette (average of current + prior year IS — encode the exact base per BOFiP, it is not a simple surcharge). Dated so it *expires* unless renewed — the reform panel then prices "renew CEBGE" as a reform, which is a genuinely topical question.
- Deficits: v1 taxes `benefice_imposable ≥ 0` and models loss-makers as zero-IS via the population's P(loss) (§3.3). **No carry-forward** (carry-forward needs firm panels we do not have): state this in the report — it biases IS *upward* mechanically.

### 2.2 CVAE (CGI 1586 ter s.) — alive until 2030
Enacted trajectory (LF 2026 cancelled the acceleration; suppression is 2030): taux maximal **0.19 %** (2024); **0.19 % + contribution complémentaire de 47.4 % of the 2025 CVAE** (2025, one-off); **0.28 %** (2026 and 2027); 0.19 % (2028); 0.09 % (2029); abrogation 2030. Encode the full **barème progressif by CA** (the max applies above 50 M€; the sub-50 M€ schedule and the 188 €? minimum and the franchise come from BOFiP-CVAE — take the bracket table from there verbatim), plus the taxe additionnelle CCI on CVAE. Assiette: valeur ajoutée fiscale, capped as % of CA — v1 proxies VA fiscale with ESANE VA (state the proxy).

### 2.3 C3S (CSS L137-30 s.)
**0.16 %** of CA above a **19 M€** abattement. Trivial to encode; C3S is also the cleanest validation line the firm module has (receipts published, base = CA which we calibrate) — treasure it.

### 2.4 What the sector/size tables make possible: the cascade note
C3S's cascading nature (CAE note 53's 2× price-effect result) is a Phase 3 behavioural/incidence story. Here it is mechanical only; the report says so.

### 2.5 CFE — refuse to fake it
CFE depends on communal valeur locative and thousands of local rates. v1 does **not** encode it as legislation. Either omit (preferred) or carry it as a calibrated per-firm lump by sector × size from DGCL/DGFiP published totals, displayed in its own visually distinct "imputed, not simulated" row. No CFE reform knob in v1.

## 3. The firm population (`entreprises/population.py`)

### 3.1 Skeleton — SIRENE
`StockUniteLegale` (+ `StockEtablissement` for geography), from files.data.gouv.fr/insee-sirene/ (§DATA list). Filter to active, market-sector unités légales subject to IS: catégorie juridique 5xxx (sociétés) as first cut, minus obvious non-IS forms — document the mapping; count check against INSEE's published "entreprises par catégorie" and DGFiP's ~2 M redevables IS. Cells: NAF A38 (fallback A88 where thin) × effectif band (SIRENE tranche) × CA band.

### 3.2 Financials — ESANE published tables
Per cell: CA, VA, EBE, résultat totals/means from ESANE ("caractéristiques comptables par secteur et taille"). Within-cell dispersion: lognormal for CA calibrated to the cell mean and any published quantiles; ratio draws (VA/CA, résultat/CA) with correlation preserved by drawing the ratios jointly per firm from a fitted 2-D distribution — invented shape, disclosed shape (report language: "distribution within sector×size cells is parametric synthesis, not measurement").

### 3.3 The two make-or-break scalars
- **P(loss) by sector × size** — 25-40 % of firms pay no IS in a normal year; without this the IS line is fiction. Source: DGFiP statistical publications on bénéfices/déficits (share of deficit-declaring firms); apply as a per-cell Bernoulli and zero the benefice.
- **benefice_imposable vs comptable** — fiscal result ≠ ESANE accounting result. v1: apply the aggregate fiscal/comptable ratio implied by (DGFiP assiette IS totals ÷ ESANE résultat totals), per broad sector where the data allows. This single ratio choice will dominate the IS residual; put it in the report's method notes with its value.

### 3.4 Calibration vs validation, restated for firms
**Spent**: firm counts per NAF×size cell (SIRENE), aggregate CA and VA per sector (ESANE), using P3's `calibrate.py` where reweighting is needed. **Validation, untouched**: IS net receipts, C3S receipts, CVAE receipts, CS 3.3 % receipts, share of firms at zero IS, effective-rate-by-size profile (DGFiP/CPO publish one — the most informative shape line, the firm analogue of D9/D1). Declared tolerances: C3S ±10 %, CVAE ±15 %, IS **±20 %** (heroic: profit dispersion + fiscal/comptable + no carry-forward all land here; declare, don't hide), zero-IS share ±10 pts.

### 3.5 Guards
NaN=0; CA ≥ 0; VA ≤ CA (flag violations); every cell's simulated count equals its calibrated count to the unit.

## 4. Runs, API, UI

`entreprises/runner.py`: same shape as Phase 1's but synchronous — 2 M firms × this formula set is sub-second **[VERIFIED at 500 k]**; no quick-tier machinery. Outputs per firm × instrument, aggregated to: total Δ by instrument; by NAF section × size class (mean Δ, Δ effective rate, share of firms affected); effective-rate histogram.

API: `POST /entreprises/simulate` `{reform: FirmReformSpec, year}` → the three tables + vintage + banner text; `GET /entreprises/baseline`. UI: third tab "Entreprises", sector×size incidence table plus one chart max, and the banner: *synthetic firm financials from public aggregates; sector/size-level only; no firm-level or top-tail claims; CFE imputed not simulated (if shown); link to reconciliation_entreprises.md*.
